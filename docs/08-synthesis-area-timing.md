## 1. 综合级检查（可综合性）

| 检查 | 工具/选项 | 结果 |
|---|---|---|
| Verilog-2005 语法、隐式信号、位宽 | `iverilog -g2005 -Wall` | **[实测] 零错误零警告** |
| lint（锁存器、多驱动、位宽、未使用、组合环） | `verilator --lint-only -Wall -Wno-DECLFILENAME` | **[实测] 零警告** |
| 锁存器 | Verilator `LATCH` 检查（含于 `-Wall`） | **[实测] 无** |
| 多驱动 / 组合环 | Verilator `MULTIDRIVEN` / `UNOPTFLAT` | **[实测] 无** |
| 隐式位宽截断 | Verilator `WIDTH` | **[实测] 无** |
| 厂商原语 / 综合属性 | 代码审查 + 无 `` (* *) `` 属性 | **[实测] 无** |
| `initial` 块 | 仅 `rv32i_ram` 的 `$readmemh`（FPGA BRAM 初始化标准写法） | 有意保留 |
| 复位 | 全同步、高有效、单时钟域 | **[实测]** |
| 时钟门控 / 多时钟 / CDC | 不使用 | **[实测] 无** |
| 三态 / `inout` | 不使用 | **[实测] 无** |

唯一被 lint 提示后**有意保留**的写法：`rv32i_ram` 的 `addr` 端口只使用

该处用一行 Verilator pragma 显式记录了决定，而不是放宽全局告警级别。

## 2. 面积/资源

### 2.1 触发器（状态位）[实测统计]

由 `tools/ff_count.py` 直接从 RTL 源码统计（读 `reg` 声明，区分时序/组合），
可随代码变化重新生成，不会与实现脱节：

```
$ python3 tools/ff_count.py rtl/core/rv32i_cpu.v rtl/regfile/rv32i_regfile.v
  rv32i_cpu.v        state subtotal  558  (+ id_ex_ctrl[22:0] = 23)
  rv32i_regfile.v    state subtotal 1024  (32 x 32)
  state bits (flip-flops, excluding memory arrays): 1582
```

| 状态组 | 位宽 | 说明 |
|---|---|---|
| PC | 32 | |
| IF/ID | 98 | valid + pc + instr + 预测字段 |
| ID/EX | 232 | valid + ctrl(23) + pc + instr + 两个操作数 + imm + 三个寄存器号 + 预测字段 |
| EX/MEM | 110 | valid + 7 个命名控制位 + pc + alu + store_data + rd |
| MEM/WB | 39 | valid + rf_we + wdata + rd |
| 陷阱/停机标志 | 70 | trap_flag/cause/pc/tval + halt_flag |
| **流水线+控制小计** | **581** | |
| 寄存器堆 | 1024 | 32×32，`RF_INIT_EN=1` 时带复位 |
| **合计** | **1605** | 不含存储器阵列 |

> 对比 `03` §2 的设计预算（约 536 + 1024）：实际 581 + 1024，多出的 45 位来自
> 陷阱寄存器（69 位）与 EX/MEM 的 `pc` 字段——这些都是实现阶段新增的**功能**字段
> （陷阱报告与 JAL/JALR 链接值生成），不是冗余。

### 2.2 组合逻辑资源 [结构估算]

| 模块 | 主要运算部件 | 估算 LUT（6 输入 LUT） |
|---|---|---|
| `rv32i_alu` | 32 位加减法器、32 位桶形移位（5 级）、两个 32 位比较器（有/无符号）、逻辑运算 | 180–260 |
| `rv32i_brcmp` | 32 位相等/大小比较 ×2（有符号/无符号） | 40–60 |
| `rv32i_immgen` | 5 种位拼接 + 符号扩展（纯布线为主） | 10–20 |
| `rv32i_decoder` | opcode/funct3/funct7 译码、合法性判定、23 位控制字装配 | 120–180 |
| `rv32i_hazard` | 6 组 5 位比较 + 优先级选择 | 30–50 |
| `rv32i_regfile` | 2 个 32:1 读多路（32 位）+ 写穿透旁路比较/多路 | 180–260 |
| `rv32i_cpu` | PC 加法器、pc+imm 加法器、2×3:1 前递多路、写回多路、对齐/字节使能、加载扩展、流水线控制 | 350–500 |
| `rv32i_ram` | 字节使能写 + 组合读（LUTRAM/BRAM 由综合器推断） | 0（映射为存储器） |
| **合计（核 + 寄存器堆）** | | **约 900–1300 LUT + 1605 FF** |

同量级开源 RV32I 核（无 Cache、无 M 扩展、五级）在 7 系列 FPGA 上通常落在
**1000–2000 LUT / 1500–2000 FF**，本估算与之相符。**该数字必须用真实综合替换**
（见 §4）。

## 3. 时序分析 [结构估算]

### 3.1 各级组合深度

| 级 | 组合路径 | 逻辑深度 | 估算延迟（中速 FPGA，-1 速度等级） |
|---|---|---|---|
| IF | PC 多路 → 指令存储器组合读 → IF/ID 建立 | 2–3 级 + LUTRAM 读 | 3.5–5 ns |
| ID | 译码 → 寄存器堆读（32:1 多路）→ 写穿透旁路 → 冒险比较 | 4–6 级 | 4–6 ns |
| **EX** | 前递多路（3:1）→ ALU（32 位加法/移位）→ 分支比较 → 目标多路 → **PC 多路** | 8–12 级 | **5–7 ns** |
| MEM | 地址译码 → 数据存储器读 → 字节/半字提取与符号扩展 → 写回多路 | 4–6 级 + LUTRAM 读 | 4–6 ns |
| WB | 寄存器堆写建立 | ≈0 | — |

**关键路径判定**：`EX` 级（前递多路 → 32 位 ALU → 分支比较 → 重定向目标 → PC 选择）
与 `MEM` 级（存储器读 + 对齐扩展）是两条最长的路径；`IF` 级在采用分布式 RAM 时也接近。

### 3.2 频率结论

- 按上表，最坏路径约 **5–7 ns** 逻辑 + 约 0.5–0.8 ns 的触发器开销 ≈ **6–8 ns**，
  对应 **约 125–165 MHz**。
- 即：**「≥100 MHz」的目标在五级切分下有余量**，且本设计**没有**为了频率做任何
  额外流水化或重定时（不需要）。
- 若存储器改为**同步读 BRAM**（大容量 FPGA 实现的常规做法），需增加 IF2 级或
  ready 握手，届时频率主要受 BRAM 访问时间限制（通常仍 ≥100 MHz）。

### 3.3 未做的时序工作（诚实记录）

- 没有做综合后静态时序分析（STA）、没有做门级仿真、没有做跨时钟域检查（单时钟域）。
- 上表是**结构估算**：逻辑深度按典型 LUT 结构计数，未经工艺库映射。

## 4. 如何得到真实数字

```sh
brew install yosys        # 或其它方式安装
make syn                  # 运行 syn/rv32i_soc.ys，输出 stat/ltp 报告
```

`syn/rv32i_soc.ys` 做的事：读入全部 RTL（含 include 路径）→ `hierarchy -top rv32i_soc`
→ `proc/opt/fsm/memory/techmap` 通用综合 → `stat`、`stat -width`、`ltp` 报告。
脚本里还预留了 `synth_xilinx / synth_ice40 / synth_ecp5` 三种工艺映射（注释状态），
映射后再 `stat` 即可得到 LUT/FF/BRAM 利用率；配合工艺库 `abc -liberty` 可得到门级面积。

## 5. 性能（CPI）[实测]

周期数与退休条数均来自仿真（`build/rtl_*.out` 的 `TB DONE` 行与日志的 `STEPS`）：

| 程序 | 周期 | 退休指令 | CPI | 说明 |
|---|---|---|---|---|
| `isa_alu` | 129 | 124 | **1.04** | 纯 ALU，几乎无控制转移 |
| `isa_imm` | 112 | 107 | **1.05** | 同上 |
| `isa_loadstore` | 115 | 106 | **1.09** | 含 load-use 停顿 |
| `hazard_wbthru` | 74 | 67 | 1.10 | 刻意制造距离 3 依赖 |
| `isa_branch` | 131 | 79 | **1.66** | 大量采纳分支（每次 2 拍冲刷） |
| `isa_jump` | 124 | 78 | 1.59 | 大量 jal/jalr |
| `corner` | 112 | 97 | 1.16 | 混合 |

**解析模型**（与实测一致）：

```
CPI = 1 + 2 × (每条指令中"被采纳的控制转移"比例)
        + 1 × (每条指令中 load-use 停顿比例)
```

- 无控制转移的代码 → 1.00–1.05；
- 典型循环（分支每 N 条采纳一次）→ 1 + 2/N；
- 小程序的 CPI 会被 5 拍流水线填充/排空显著抬高（如 5 条指令的程序 CPI=2.0），
  这是固定开销而非稳态性能。

**取舍说明**：分支在 EX 解析（而非 ID）为每次采纳多付 1 拍，换来只有一套前递/互锁逻辑；
不实现分支预测（规格不要求）。两者都记入 `03` §12 的未来改进。
